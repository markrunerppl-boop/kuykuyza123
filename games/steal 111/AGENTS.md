# AGENTS.md - คู่มือและกฎการทำงานสำหรับ AI Agent (Kuykuy Project)

เป้าหมายสูงสุด: เพิ่มหรือแก้ไขฟังก์ชันให้สำเร็จในคำสั่งเดียว (One-Shot Execution) ด้วยความเร็วสูงสุด แม่นยำ ใช้ทรัพยากรน้อยที่สุด และไม่กระทบระบบเดิม

## 1. ลำดับการอ่านข้อมูล (Context & File Lookup Priority)
1. ค้นหาข้อมูลจากไฟล์ในเครื่องก่อนเรียกใช้ Roblox MCP เสมอ ตามลำดับนี้:
   - **อันดับ 1:** อ่านไฟล์สคริปต์หลักที่ต้องการแก้ไข (เช่น `main.lua`) เฉพาะบรรทัดหรือฟังก์ชันที่เกี่ยวข้อง (หากยังไม่มีไฟล์ให้สร้างใหม่ตามโครงสร้างที่สั่ง)
   - **อันดับ 2:** อ่านไฟล์ `1_AI_Overview.md` เพื่อทำความเข้าใจภาพรวมของแมพ สถิติ และรายชื่อ Remotes เบื้องต้น
   - **อันดับ 3:** ค้นหาเฉพาะคำสำคัญ (Search/Grep) ในไฟล์ Pretty-Print JSON ทั้ง 2 ไฟล์:
     * `2_Network_And_Modules.json` (หรือ `2_Network*.json`): ดู `LiveNetworkTraffic` (เพื่อดึง Arguments ของจริงที่ดักจับได้), `RemoteEndpoints`, `LoadedModuleExports` และ `ScriptPaths`
     * `3_Gameplay_POIs.json` (หรือ `3_*POIs.json`): ดูพิกัดและ Path ของ `ProximityPrompts`, `ClickDetectors`, `NPCs_And_Mobs`, `Tools_And_Items`, `ValueObjects` และ `Tagged_And_Attributed`
2. **[ห้ามเด็ดขาด]:** ห้ามอ่านไฟล์ `.json` ทั้งไฟล์ในครั้งเดียว ให้ใช้เครื่องมือค้นหาเฉพาะบรรทัด (`grep` / `search`) เท่านั้นเพื่อประหยัด Token (และห้ามเปิดไฟล์เก่าตระกูล `MapDumper_Export_*.json` หากหลงเหลืออยู่ในโฟลเดอร์)
3. ใช้ข้อมูลที่มีอยู่แล้วต่อยอดทันที ห้ามค้นหาข้อมูลเดิมซ้ำ

## 2. กฎควบคุมการใช้ Roblox MCP (Zero-Latency MCP Rules)
1. เรียกใช้ Roblox MCP เฉพาะเมื่อข้อมูลใน `1_AI_Overview.md`, `2_Network_And_Modules.json` และ `3_Gameplay_POIs.json` ไม่เพียงพอต่อการทำงานจริงเท่านั้น (เช่น ต้องแกะโค้ดภายในฟังก์ชันที่ไม่ได้อยู่ใน `LiveNetworkTraffic`)
2. ห้ามเรียก `get-script-content`, `script-grep`, `search-instances` หรือ `get-data-by-code` ซ้ำในโมดูลหรือข้อมูลที่เคยดึงมาแล้วในแชทปัจจุบัน
3. ค้นหาเฉพาะ Script, Function หรือข้อมูลที่เกี่ยวข้องกับปัญหาโดยตรง
4. เมื่อพบข้อมูลหรือต้นเหตุที่ต้องการแล้ว ให้หยุดสำรวจและลงมือแก้ไขโค้ดทันที ห้ามวนค้นหาซ้ำโดยไม่มีข้อมูลใหม่

## 3. กฎการพัฒนาและแก้ไขโค้ด (Direct Coding & Luau Standards)
1. **ใช้ Direct Edit เท่านั้น:** แก้ไขโค้ดลงในไฟล์เป้าหมายโดยตรงด้วยเครื่องมือแก้ไขไฟล์ (Replace/Edit) ไม่ต้องอธิบายขั้นตอนระหว่างทำ
2. **ไม่ต้องสร้างไฟล์ Backup:** ยกเลิกการสร้างไฟล์สำรอง `[ชื่อไฟล์]_backup.lua` อัตโนมัติก่อนแก้ไขไฟล์ (ผู้ใช้จัดการ Version Control เอง) เพื่อลดเวลาการอ่านและเขียนไฟล์ซ้ำซ้อน
3. **งดใช้ Sandbox/Terminal:** ไม่ต้องรันคำสั่งผ่าน Shell/Sandbox เพื่อตรวจสอบไฟล์หรือรันสคริปต์ทดสอบ เพื่อหลีกเลี่ยงอาการหน่วงเวลา (Sandbox Execution Timeout)
4. **มาตรฐานโค้ด Luau สำหรับระบบ Automated Loop:**
   - แยกการทำงานของแต่ละลูปด้วย `task.spawn` และใช้ `task.wait()` เสมอ (ห้ามใช้ `wait()` เปล่า)
   - ครอบ `pcall` ในทุกจุดที่มีการยิง Remote (`FireServer` / `InvokeServer`) และ **ต้องมีระบบ Timeout Guard (3-4 วินาที) สำหรับ `InvokeServer` เสมอ** เพื่อป้องกันเธรดค้างถาวรหากเซิร์ฟเวอร์ไม่ตอบกลับ
   - สำหรับแมพที่มีระบบฐานผู้เล่น (`Plots`) ต้องเขียนฟังก์ชันค้นหาและแคชฐานของ `LocalPlayer` อัตโนมัติเสมอ ห้าม Hardcode หมายเลข Plot
   - ทุกฟังก์ชันอัตโนมัติ (เช่น ซื้อ, ขาย, เปิดแพ็ก, หลอมยูนิต) ต้องมีบันทึกประวัติการทำงานลง Circular Buffer (`Stats.logs` / `logAction`) เพื่อให้ผู้ใช้ตรวจสอบสถานะการทำงานผ่านแท็บบันทึกบนหน้าต่าง UI ได้แบบ Real-Time
5. ห้ามแก้ไขระบบเดิม โครงสร้าง UI เดิม หรือไฟล์อื่นที่ไม่เกี่ยวข้อง และห้ามสร้างระบบใหม่ทับระบบเดิมหากสามารถนำระบบเดิมมาใช้ได้
6. หากติดปัญหา ให้ระบุปัญหาและสาเหตุอย่างชัดเจน ห้ามวนค้นหาหรือทดลองซ้ำโดยไม่มีแนวทางใหม่

## 4. กฎการตรวจสอบและทดสอบ (Verification)
1. ตรวจสอบความถูกต้องของโค้ดด้วยการอ่านทวน (Static Code Review) เฉพาะจุดที่เพิ่มหรือแก้ไข
2. ตรวจสอบว่าไม่มีการแก้ไขหรือทำให้ระบบเดิมเสียหายก่อนแจ้งผลลัพธ์

## 5. กฎความปลอดภัยของเซสชัน (Live Test Session Protection Rules - กฎป้องกันการรบกวนเซสชันทดสอบ)
เป้าหมาย: ป้องกันการรบกวนเกมและลดความเสี่ยงจากการทำงานของ Script ระหว่างที่ผู้ใช้กำลังเล่นเกม

1. สามารถอ่าน วิเคราะห์ และแก้ไขไฟล์ Lua ในเครื่องได้ตามปกติ โดยแยกการแก้ไขไฟล์ออกจากการทดสอบในเกมอย่างชัดเจน
2. ห้าม Run/Execute อัตโนมัติ หรือ Re-execute Script เข้าสู่ Session เกมที่กำลังเล่นโดยอัตโนมัติ
3. ห้ามสั่ง Disconnect, Rejoin, Restart หรือปิดเกม
4. ห้ามเรียก RemoteEvent หรือ RemoteFunction เพื่อทดลองคำสั่งกับเกมจริงระหว่างการแก้ไขโค้ด
5. ห้ามทดลองคำสั่งที่เปลี่ยนสถานะเกมหรือส่งผลต่อผู้เล่นอื่น
6. ห้ามควบคุม Session เกมที่กำลังทำงานโดยไม่ได้รับอนุญาต และห้ามพยายามหลบเลี่ยง Anti-Cheat หรือระบบ Kick ของเกม
7. หากพบข้อผิดพลาดที่อาจเกี่ยวข้องกับระบบป้องกันของเกม ให้หยุดและแจ้งผู้ใช้ทันที (ห้ามรับประกันว่าจะป้องกัน Error 267 ได้ 100%)
8. เมื่อแก้ไขไฟล์เสร็จ ให้หยุดและรายงานผลทันทีโดยไม่ Execute เอง
